11.Plugin System Specification

Bangun Plugin System yang modular, scalable, dan hot-pluggable.

Plugin tidak boleh mengubah source code Core.

Seluruh komunikasi antara Plugin dan Core harus melalui Registry, Event Bus, Interface, atau Hook.

Core tidak boleh mengetahui implementasi internal plugin.

Plugin dapat di-install, di-enable, di-disable, di-update, dan di-uninstall tanpa mengubah kode utama.

---

Struktur Plugin

Setiap plugin berada pada folder:

plugins/
    weather/
        plugin.json
        README.md

        commands/
        agents/
        skills/
        tools/
        hooks/
        providers/
        mcp/
        knowledge/
        assets/

Seluruh folder bersifat opsional.

Plugin hanya memuat folder yang dibutuhkan.

---

Manifest

Setiap plugin WAJIB memiliki:

plugin.json

Contoh:

{
  "id": "weather",

  "name": "Weather Plugin",

  "version": "1.0.0",

  "author": "Developer",

  "description": "Weather service",

  "homepage": "",

  "license": "MIT",

  "entry": "index.js",

  "dependencies": [],

  "commands": true,

  "agents": true,

  "skills": true,

  "tools": true,

  "hooks": true,

  "providers": false,

  "mcp": false,

  "knowledge": true
}

Manifest digunakan Plugin Manager untuk melakukan registrasi otomatis.

---

Plugin Manager

Saat startup:

1. Scan folder plugins/

2. Cari plugin.json

3. Validasi manifest

4. Validasi dependency

5. Load plugin

6. Register seluruh komponen

7. Jalankan lifecycle plugin

Plugin yang gagal tidak boleh menghentikan Core.

Plugin gagal hanya diberi status Failed.

---

Plugin Lifecycle

Plugin memiliki lifecycle:

- onLoad()
- onEnable()
- onDisable()
- onUnload()
- onUpdate()

Core akan memanggil lifecycle sesuai kondisi.

---

Registry

Plugin tidak boleh langsung mengakses Core.

Gunakan Registry.

Registry minimal terdiri dari:

- Command Registry
- Tool Registry
- Skill Registry
- Agent Registry
- Provider Registry
- MCP Registry
- Hook Registry
- Knowledge Registry

Plugin hanya melakukan:

register()

unregister()

---

Dependency

Plugin boleh memiliki dependency.

Contoh:

{
    "dependencies": [
        "filesystem>=1.0.0",
        "github>=2.1.0"
    ]
}

Plugin Manager harus:

- mengecek dependency
- mendeteksi konflik
- menolak plugin jika dependency belum terpenuhi

---

Isolation

Setiap plugin berjalan pada namespace sendiri.

Plugin tidak boleh:

- mengubah database plugin lain
- mengakses data plugin lain
- mengubah konfigurasi Core
- memodifikasi memory user secara langsung tanpa API

Semua akses dilakukan melalui Plugin API.

---

Storage

Plugin dapat memiliki storage sendiri.

Contoh:

atau

SQLite sendiri.

Core tidak boleh menyimpan data internal plugin.

Event Bus

Seluruh komunikasi menggunakan Event Bus.

Plugin boleh:

emit()

listen()

Tidak boleh saling memanggil fungsi internal plugin lain.

---

Hot Reload

Plugin harus mendukung:

Enable

Disable

Reload

Uninstall

Install

tanpa perlu restart bot apabila memungkinkan.

---

Error Handling

Jika plugin mengalami error:

- Core tetap berjalan.
- Plugin diberi status Error.
- Error dicatat pada log.
- Plugin lain tetap berjalan normal.

Plugin tidak boleh menyebabkan seluruh bot crash.

---

Security

Plugin tidak memiliki akses penuh.

Hak akses ditentukan melalui manifest.

Contoh:

{
    "permissions": [
        "filesystem.read",
        "filesystem.write",
        "network",
        "provider",
        "knowledge",
        "scheduler"
    ]
}

Plugin Manager wajib memvalidasi permission sebelum plugin dijalankan.

---

Tujuan

Plugin System Elynia harus menjadi sistem modular modern yang memungkinkan developer menambahkan fitur baru (Command, Tool, Agent, Skill, MCP, Provider, Knowledge, dan Hook) hanya dengan menambahkan folder plugin, tanpa perlu mengubah source code Core sama sekali.
